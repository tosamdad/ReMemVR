간편 로그인(카카오, 구글) 준비와 첫 배포 후 할 일

2026-10-04 기준 카카오디벨로퍼스와 Google Cloud 콘솔 공식 문서를 확인해 정리했다.
간편 로그인은 선택 기능이다. 키를 넣지 않으면 로그인 화면의 카카오, 구글 버튼은 "간편 로그인은 준비 중이에요" 안내만 띄우고, 이메일 가입과 로그인은 그대로 쓸 수 있다.

키와 비밀번호는 채팅이나 문서에 적지 않고 GitHub 저장소의 Settings > Secrets and variables > Actions > New repository secret 에만 넣는다.
Secret 을 넣거나 바꾼 뒤에는 배포가 한 번 돌아야 서버 설정 파일에 반영된다(코드 변경이 없으면 Actions > Deploy > Run workflow).

아래에서 사이트주소는 GitHub Secret SITE_URL 에 넣은 값이다(예: https://rememvr.co.kr). 끝에 / 를 붙이지 않는다.


1. 카카오 로그인

필요한 Secret: KAKAO_REST_API_KEY, KAKAO_CLIENT_SECRET (둘 다 필요)

1) https://developers.kakao.com 에 카카오 계정으로 로그인하고 [내 애플리케이션] 에서 [애플리케이션 추가하기] 로 앱을 만든다. 앱 이름은 르멤버, 회사명은 운영 주체 이름을 적는다.
2) [앱] > [제품 링크 관리] > [웹 도메인] 에 사이트주소를 등록한다(예: https://rememvr.co.kr). www 주소로도 접속된다면 그 주소도 함께 등록한다.
3) [카카오 로그인] > [사용 설정] 의 [상태] 를 ON 으로 바꾼다.
4) [앱] > [플랫폼 키] > [REST API 키] 를 연다.
   - [리다이렉트 URI] 에 사이트주소/auth/kakao/callback 을 정확히 등록한다(예: https://rememvr.co.kr/auth/kakao/callback).
   - [클라이언트 시크릿] 에서 코드를 확인한다. 새 REST API 키는 클라이언트 시크릿이 켜진 상태로 만들어지므로 이 코드를 반드시 함께 등록해야 한다.
   - REST API 키 값은 KAKAO_REST_API_KEY, 클라이언트 시크릿 코드는 KAKAO_CLIENT_SECRET 에 넣는다.
5) [카카오 로그인] > [동의항목] 에서 닉네임(profile_nickname) 을 필수 동의로 켠다. 닉네임은 모든 앱에서 설정할 수 있다.
6) 이메일(account_email) 은 비즈 앱에서만 켤 수 있다. 사업자등록번호가 없어도 [앱] > [일반] > [비즈니스 정보] > [개인 개발자 비즈 앱] 에서 본인인증 후 전환할 수 있다. 전환 뒤 [동의항목] 에서 카카오계정(이메일) 을 필수 동의로 켠다.
   - 이메일을 켜지 않아도 로그인은 된다. 이때 회원 이메일은 kakao_회원번호@users.rememvr.local 같은 임시 주소로 저장되고, 회원이 설정 > 프로필 수정에서 실제 이메일로 바꿀 수 있다. 다만 비밀번호 재설정 메일과 목소리 완성 알림을 받으려면 실제 이메일이 필요하므로 전환을 권한다.
7) 이미 같은 이메일로 가입한 계정이 있으면 간편 로그인을 자동으로 연결하지 않고, 처음 가입한 방법으로 로그인하라고 안내한다. 이메일 가입은 주소 소유를 확인하지 않으므로, 남의 이메일로 먼저 가입해 둔 사람이 진짜 주인의 계정을 가로채지 못하게 하려는 것이다.


2. 구글 로그인

필요한 Secret: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET (둘 다 필요)

1) https://console.cloud.google.com 에서 화면 위쪽 프로젝트 선택 메뉴로 새 프로젝트를 만들고(이름 예: rememvr), 만든 프로젝트가 선택되어 있는지 확인한다.
2) 메뉴 > Google 인증 플랫폼(Google Auth Platform) 으로 가서 [시작하기] 를 누른다.
   - 앱 정보: 앱 이름 르멤버, 사용자 지원 이메일은 운영 메일을 고른다.
   - 대상: 외부(External) 를 고른다. 내부는 Google Workspace 조직 사용자만 쓸 수 있다.
   - 연락처 정보: 구글 안내를 받을 개발자 이메일을 적는다.
   - Google API 서비스 사용자 데이터 정책에 동의하고 [만들기] 를 누른다.
3) [브랜딩] 에서 승인된 도메인에 도메인만 적는다(예: rememvr.co.kr, https:// 와 www 는 빼고). 리디렉션 URI 를 만들기 전에 도메인부터 넣어야 한다.
   - 앱 홈페이지는 사이트주소, 개인정보처리방침은 사이트주소/settings/privacy, 서비스 약관은 사이트주소/settings/terms 를 적는다(로그인 없이 열리는 화면이다).
   - 로고는 올리지 않는다. 로고를 올리면 구글 심사가 시작된다.
4) [데이터 액세스] 는 따로 설정하지 않아도 된다. 르멤버는 기본 범위(openid, email, profile)만 쓰고, 이 범위는 구글 심사가 필요 없다.
5) [클라이언트] 에서 [클라이언트 만들기] 를 누른다.
   - 애플리케이션 유형: 웹 애플리케이션
   - 이름: 아무 이름(예: 르멤버 웹)
   - 승인된 JavaScript 원본(출처): 비워 둔다(서버에서 처리하는 방식이라 필요 없다).
   - 승인된 리디렉션 URI: 사이트주소/auth/google/callback 을 정확히 등록한다(예: https://rememvr.co.kr/auth/google/callback).
6) 만들기를 누르면 클라이언트 ID 와 클라이언트 보안 비밀번호가 나온다. 보안 비밀번호는 이때만 전체가 보이므로 바로 GitHub Secret 에 넣는다.
   - 클라이언트 ID(…apps.googleusercontent.com 으로 끝남) 는 GOOGLE_CLIENT_ID, 클라이언트 보안 비밀번호는 GOOGLE_CLIENT_SECRET 에 넣는다.
   - 보안 비밀번호를 잃어버리면 클라이언트 화면에서 새 보안 비밀번호를 추가하고 옛것은 사용 중지 후 삭제한다.
7) [대상](오디언스로 보일 수도 있다) 에서 게시 상태가 테스트 중이면 [앱 게시] 를 눌러 프로덕션으로 바꾼다. 기본 범위만 쓰므로 심사 없이 바로 바뀐다.


3. 자주 막히는 부분

- 리디렉션 주소는 글자 하나까지 같아야 한다. https 와 http, 끝의 / 유무, www 유무가 다르면 카카오는 KOE006, 구글은 redirect_uri_mismatch 오류가 난다. SITE_URL 과 콘솔에 등록한 주소의 앞부분이 같아야 한다.
- 사이트에 www 주소와 www 없는 주소가 모두 열린다면 두 주소의 리디렉션 URI 를 모두 등록하거나, 한쪽으로 접속이 모이게 SITE_URL 을 정한다.
- 구글 콘솔에서 바꾼 리디렉션 주소는 반영까지 5분에서 몇 시간이 걸릴 수 있다.
- 구글 클라이언트는 6개월 동안 한 번도 쓰이지 않으면 자동 삭제된다(30일 전에 메일 안내).
- 카카오 앱과 구글 프로젝트는 운영자 개인 계정이 아니라 오래 쓸 운영용 계정으로 만드는 것이 좋다.


4. 첫 배포 뒤 할 일

1) 이번 PR 을 main 에 머지하면 자동으로 실서버에 배포되고, DB 에 새 테이블과 동화 12편이 들어간다.
2) 사이트주소/admin 에 접속하면 관리자가 한 명도 없을 때만 [최초 관리자 설정] 화면이 열린다. GitHub Secret OPS_TOKEN 에 넣은 값과 관리자 아이디, 이름, 비밀번호를 입력해 첫 관리자를 만든다. OPS_TOKEN 값을 따로 적어 두지 않았다면 새 값을 만들어 Secret 을 바꾼 뒤 배포를 한 번 돌리고 그 값을 쓴다.
3) 관리자 화면 > 운영 설정에서 서비스 정보(고객센터 이메일, 전화, 운영 시간)와 관리자 알림 메일을 채운다.
4) 회원으로 가입해 목소리 연구실에서 직접 녹음하고 제출한 뒤, 관리자 화면 > 목소리 생성 관리에서 승인하면 ElevenLabs 로 목소리가 만들어지고 동화 12편이 차례로 준비된다.
5) 아이 질문 기능은 2026-10-04 결정에 따라 보류 상태다(Gemini 약관이 18세 미만 대상 서비스 사용을 금지). 다시 켜려면 아이 대상 사용을 허용하는 답변 AI 로 바꾸는 개발이 먼저 필요하다. 등록해 둔 GEMINI_API_KEY 는 지금은 쓰이지 않는다.
